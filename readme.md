# Non-Ergodic Mess3 Geometry Experiment

This repo studies a simple synthetic setting where a transformer is trained on a **non-ergodic mixture of Mess3 processes** and then analyzed through the geometry of its residual stream.

The main goal is to understand whether the model’s internal representations reflect the **true Bayesian belief geometry** of the underlying hidden process.

## References

- Shai, Adam, Loren Amdahl-Culleton, Casper L. Christensen, Henry R. Bigelow, Fernando E. Rosas, Alexander B. Boyd, Eric A. Alt, Kyle J. Ray, and Paul M. Riechers. 2026. **“Transformers Learn Factored Representations.”** *arXiv preprint arXiv:2602.02385*.

- Shai, Adam, Lucas Teixeira, Alexander Oldenziel, Sarah Marzen, and Paul Riechers. 2024. **“Transformers Represent Belief State Geometry in Their Residual Stream.”** *Advances in Neural Information Processing Systems* 37: 75012–75034.

## Main idea

We construct a dataset from multiple Mess3 components with different parameters.

For each training sequence:

- one Mess3 ergodic component is sampled at the start
- the whole sequence is generated from that one component
- the component does not change within the sequence

This makes the overall process **non-ergodic**.

A small decoder-only transformer is then trained with **next-token prediction**.  
After training, we compare the transformer’s residual stream to the exact Bayesian belief states of the underlying hidden Markov model.

## Why this is interesting

This is a toy version of a problem that also shows up in language modeling.

Real language data are not generated by one stationary source. Different users, domains, styles, or tasks can behave like different latent generators. So a model often has to do two things at once:

1. infer which latent source is currently active
2. track the evolving state within that source

This experiment makes that structure very explicit.

## What is in this repo

The code does four main things:

1. **Generate data** from a non-ergodic mixture of Mess3 components
2. **Train a transformer** on next-token prediction
3. **Compute exact Bayesian belief states** for the same sequences
4. **Analyze residual stream geometry** using linear probes and simplex plots

## Geometry being tested

The global hidden state has 9 states total:

- 3 Mess3 components
- each with 3 local hidden states

Because the process never switches components mid-sequence, the full hidden-state belief naturally splits into:

- a posterior over **which component** generated the sequence
- a local posterior over **which hidden state** the sequence is in inside that component

So the expected geometry is a **two-scale geometry**:

- global component-level structure
- local within-component belief structure

## Notes

- The script currently runs on CPU by default.
- For larger sequence lengths, exhaustive prefix enumeration becomes expensive, so the plotting code caps the prefix length used for the exact geometry plot.
- Some analyses are mainly qualitative and should be read as proof-of-concept rather than final large-scale results.

## Summary of the result

The main qualitative question is:

**Does the transformer learn a residual-stream geometry that reflects the true belief geometry of the hidden process?**

The answer in this setup is broadly:

- the strongest learned structure is usually the posterior over ergodic component
- later positions and deeper layers make that structure clearer
- within high-confidence component regions, some finer local hidden-state structure is also visible

So the learned geometry is better described as a **mixture of belief geometries** rather than one single global shape.

## Possible extension

A useful next analysis would be to compare the transformer’s next-token loss against the **exact Bayesian next-token predictor** for the same process. That would show how close the model is to the Bayes-optimal predictor, not just whether its geometry looks similar.
